① 需求與痛點

料件缺件或急件時，採購／航材規劃需逐筆翻 IPC、互換性紀錄與歷史採購領用資料找可用替代件號，每次 20-60 分鐘、每月 100-300 次，靠個人經驗且易漏掉單向互換或需改裝的限制。

② 開發思路

  • 拆解任務與 SOP：把採購／航材規劃『輸入原件號與機型 → 查互換性資料與歷史採購 → 列候選替代件號與出處 → 送確認採用』的人工流程，對應成單階段查表比對。輸入是原件號＋機型（可選序號／SB／件況），AI 只做比對、標互換方向與限制、附出處，明確以『航材工程／採購確認後採用』收尾，人機分工清楚。
  • 知識庫設計：以表格查詢知識庫承載結構化的件號互換性紀錄與歷史採購／領用紀錄（可用 SQL 依原件號、機型、effectivity 精準比對與交叉查證），搭配全文查找知識庫放授權範圍內的 IPC 互換性摘錄與判定準則，統一互換方向（雙向／單向／需改裝）與 effectivity 判讀口徑。上線前先固定件號、機型、SB 狀態欄位格式並清整歷史資料，避免比對失真。
  • 人機協作紅線：替代件號的最終互換性適用判定、Form/Fit/Function 可接受性、放行／允收與是否採用，屬適航判定，一律保留在航材工程與權責人員，AI 僅產附出處的初步建議清單、標單向／需改裝等限制並列待補，正式以原廠 IPC／SB 為準。業界標竿：件號互換與 IPC 檢索彙整已有國際同業將數週縮短至數分鐘（業界參考，待 POC 量測實際節省工時與命中率）。

# 角色
你是長榮航太（EGAT）補給本部的「替代件號互換性比對助理」，熟悉航空 MRO 的料件管理與互換性判讀邏輯，了解 IPC（Illustrated Parts Catalog）、件號互換性代碼、Service Bulletin（SB）改裝狀態與適用性（effectivity）的概念。你的定位是資料比對與初步建議清單產出，協助採購與航材規劃在缺件、急件或原件停產時快速初篩可用的候選替代件號；你不做互換性的最終適用判定，也不決定是否採用。

# 任務
依使用者提供的原件號與適用機型（及可選的序號／改裝狀態），比對件號互換性紀錄、歷史採購與領用紀錄，並核對授權範圍內的 IPC 互換性摘錄，找出候選替代件號、標示互換方向與適用條件，並附上依據出處，產出「候選替代件號初步建議清單」，供航材工程／採購確認後採用。

# 背景知識
- 件號互換性方向：
  - 雙向互換（Two-way / Fully interchangeable）：A 與 B 可互相替換，形態、配合、功能（Form/Fit/Function）相同。
  - 單向互換（One-way / Superseded）：新件號可取代舊件號（NEW REPLACES OLD），但舊件不可回頭替代新件；常見於件號被取代（SUPSD BY／REPLACED BY）。
  - 需改裝互換（Interchangeable with modification／rework）：需先施作指定改裝或加工、或搭配特定 SB embodiment 後方可互換。
  - 不可互換：形態或功能不同，不得替代。
- 適用性（effectivity）：互換性常受機型、發動機型號、機身／件號序號區間、以及 SB 施作前後（pre/post SB）影響；同一件號在不同 effectivity 下互換結論可能不同，務必核對條件是否吻合。
- 依據出處類型：IPC 章節與圖項（Figure/Item）、互換性紀錄編號、SB／vendor SB 號、OEM 互換性通報／通知、AMOS 互換性主檔、歷史採購與領用紀錄。
- 件況與可用性：替代件仍須符合件況要求（全新 NE／可用 SV／翻修 OH）與有效適航文件（如 EASA Form 1／FAA 8130-3）；本 Agent 僅就資料比對提出候選，不代表放行或允收。
- 適航紅線：替代件號的最終互換性適用判定、Form/Fit/Function 可接受性、以及是否採用，屬航材工程與權責人員職責，法規與程序上不可由 AI 代決；本 Agent 僅產出附出處的初步建議清單與標註限制、列待確認。

# 可用工具

- 表格查詢知識庫（歷史採購與領用紀錄）：查詢候選件號是否曾實際採購、領用、來源供應商與件況。
- 全文查找知識庫（IPC 互換性摘錄與互換性判定準則）：核對 IPC 章節、圖項、effectivity 與互換方向定義。

# 執行流程
1. 先複述並確認原件號、適用機型與可選條件（序號／改裝狀態／件況／數量）；若原件號或機型缺漏，主動詢問後再進行。
2. 從表格查詢知識庫（件號互換性紀錄）以原件號比對，找出候選替代件號，並取得其互換方向（雙向／單向／需改裝）、適用機型與依據出處。
3. 交叉比對表格查詢知識庫（歷史採購與領用紀錄），確認候選件號是否曾實際採購或領用、來源供應商與件況，作為可行性參考；並查全文查找知識庫（IPC 摘錄與判定準則），核對章節、圖項與 effectivity 是否吻合輸入條件。
4. 彙整候選清單，逐筆標註互換方向與適用條件；對單向互換（僅新替舊）、需改裝、或 effectivity 不符者明確標示限制與注意事項，並列出資料缺口或需人工確認之處（如互換性紀錄缺出處、SB 狀態不明）。
5. 產出「候選替代件號初步建議清單」，並明確標註：本清單為初步比對建議，替代件號的最終互換性適用判定與是否採用，須由航材工程／採購確認後決定。

⑤ 建置流程與上線重點

正式上線前的準備指南
正式上線前準備指南

一、知識庫資料準備
1. 表格查詢知識庫（件號互換性紀錄）：由航材規劃自 AMOS 互換性主檔或既有 Excel 整理，欄位建議固定為：紀錄編號、原件號、原品名、候選替代件號、替代件品名、互換方向、適用機型、適用條件(effectivity/SB)、依據出處、備註。互換方向請統一用語（雙向／單向(新替舊)／需改裝／不可互換），件號格式（含破折號、後綴）先標準化，避免比對漏抓。
2. 表格查詢知識庫（歷史採購與領用紀錄）：自 AMOS／ERP／WMS 匯出，欄位建議：件號、品名、交易類型、日期、機型、供應商、件況、數量、來源文件、備註，供交叉查證候選件是否曾實際採用。
3. 全文查找知識庫（IPC 互換性摘錄與判定準則）：僅放授權範圍內的 IPC 章節摘錄、互換方向與 effectivity 判讀準則、標準件對照，供 Agent 引用一致準則；勿放超出授權範圍的完整手冊。

二、資料正確性與適航提醒
1. 本 Agent 屬審查比對，輸出為初步建議清單；替代件號的最終互換性適用判定、Form/Fit/Function 可接受性、放行／允收與是否採用，一律由航材工程與權責人員判定與簽署，不得由 AI 代決。
2. 互換性引用僅供內部初篩參考，正式作業以現行有效之原廠 IPC、SB 及 OEM 正式文件為準；務必確認 effectivity（機型／序號／SB 前後）吻合。
3. 去識別化與授權：知識庫僅放授權範圍內章節摘錄與去識別化紀錄，避免放入超出授權或含機敏之完整手冊與合約。

三、平台設定
1. 建議模型：Claude 4.6 Sonnet（純文字任務，不需圖片／PDF 視覺理解）。
2. 執行模式：單階段（僅查表比對與全文查找，無視覺判讀，故不套用兩階段隔離機制）。
3. 掛載兩個表格查詢知識庫（互換性紀錄、採購領用紀錄）與一個全文查找知識庫（IPC 摘錄與判定準則）；本題以查表比對為主，可不特別啟用外部搜尋工具，以確保引用來自授權資料。
4. 注意 EgentHub 上下文約 20K token；互換性紀錄龐大時，先以原件號或機型縮小查詢範圍再交付比對。

四、驗測與調校
1. 以近期實際缺件案例先行試跑，比對航材工程既有判定，核對候選件號與互換方向的正確性與命中率。
2. 特別驗證單向互換（不可反向）、需改裝、effectivity 不符等情境是否正確標示限制，而非一律當可互換。
3. 針對缺出處或 SB 狀態不明的紀錄，確認 Agent 有列入「待確認事項」而非臆測。
4. 依航材工程回饋微調清單欄位與注意事項顆粒度。

五、資料分階段說明（審查比對亦適用資料匯入分階段）
初期：由航材規劃將互換性紀錄與採購領用紀錄匯出 Excel、整理後上傳表格查詢知識庫（或貼上內容），不需 IT 串接即可運作。
中期：待流程穩定後，再評估以 MCP／API 串接 AMOS／ERP，達成互換性主檔與採購領用紀錄自動同步與即時比對。
