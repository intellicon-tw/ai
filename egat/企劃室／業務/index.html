這一區是最貼近客戶第一線的三題——客戶英文詢問回覆草稿、維修合約條款摘要與版本比對、報價工時歷史數據解讀，場景都很具體，輸入、輸出與處理邏輯都寫得清楚，而且戰略價值高（前兩題列為高優先），是能直接替業務與報價人員省下大量重複工的實用組合。亮點是這幾隻 Agent 幾乎不碰 OEM 授權紅線，卡點主要在「你們自己的真資料」有沒有到位：要把英文回覆做準，得餵進實際的維修能量清單（capability list）、有效認證證書清單與歷史回覆範例；合約比對要有去識別化的新舊版合約、標準條款範本與風險條款清單；報價工時解讀初期先靠 AMOS／ERP 匯出的歷史工時與報價 Excel（欄位要對齊機型、工作範圍、實耗工時），中期再評估串接 AMOS 報價模組。這些補齊了，回覆的引用出處、合約的差異標註、估價的相似案區間才會可信、才敢讓同仁拿去用；記得所有產出都是草稿，最終寄出、用印與核價一律回到業務與主管。以下每一頁對應一個需求，點進去可看到：需求與痛點 → 開發思路 → 完整提示詞 → 知識庫設計 → 建置流程 → 驗測情境。
