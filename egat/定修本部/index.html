任務盤點表轉化的 POC 解題示範（每題一頁，含完整開發思路與提示詞）

部門 定修本部共 4 款 Agent POC理念 人機協作 · 非全自動

定修本部這一盤是整個 MRO 現場的核心：從技師的技術文件問答、NRC 缺陷描述與修理方案草稿，到工卡交接摘要、定檢缺陷的重複性分析，四題場景都很具體、輸入與輸出也講得清楚，戰略價值高、使用頻率大（光技術文件問答一個月就上千次查詢），是最值得優先做深的部門之一。亮點是每題都守住適航紅線——AI 只做檢索、彙整、產草稿與標異常，修理方案判定、檢驗員放行與簽署一律回到授權持照人員。要真正把 Agent 做出來，最關鍵是補三類真實資料：一是可放進知識庫的「OEM 授權範圍內」手冊章節摘錄與內部工程通報（務必先確認授權邊界）、二是去識別化的歷史 NRC 案例與標準缺陷用語表、三是 AMOS 實際匯出的工卡清單與缺陷／PIREP 欄位範例（含欄位定義與 SOP 步驟），初期先用匯出 Excel 上傳解讀、中期再評估 AMOS 串接。以下每一頁對應一個需求，點進去可看到：需求與痛點 → 開發思路 → 完整提示詞 → 知識庫設計 → 建置流程 → 驗測情境。

#1

技術文件問答助手（授權範圍內）

知識問答

技師在多為英文的龐大技術文件中翻查授權章節與工程通報，每次 15-40 分鐘、每月 1,500-3,000 次，數百位技師重複耗時。

 #2

NRC 缺陷描述與修理方案草稿助理

標準化作業

結構／系統工程師撰寫每件 NRC 缺陷描述與修理方案要 30-90 分鐘、每月 800-1,500 件，英文用語與引用出處靠人工翻查歷史案例，費時且格式不一。

 #3

工卡執行紀錄摘要與交接報告助手

內容生成

帶班負責人每班交接前要手動翻查工卡清單、統計進度與挑異常，每班耗 30-60 分鐘，全公司各機各班每月 400-800 次，易漏標待料與待檢驗項。

 #4

定檢缺陷歷史與重複性缺陷分析

數據解讀

工程分析人員每次要花 2-4 小時翻 AMOS 缺陷紀錄手動歸 ATA 章節、找重複性缺陷，每月 20-40 次，量大又易漏、判讀口徑不一。
