① 需求與痛點

訓練部每月要排 2-4 次招訓梯次，人工協調課程、教官、教室與模擬設備每梯次要花 1-2 天，教官撞期、教室與設備重複占用、容量不足等衝突常要反覆對表才發現。

1
應用場景與業務流程幫誰解決什麼問題？
幫訓練部行政把『這一期要開的課程』對上『教官／教室／模擬設備』的資源限制，快速產出一份梯次排程草案並自動抓出衝突。原本每梯次要人工對表 1-2 天、每月 2-4 次；改由 Agent 先排草案、標衝突、給調整選項，行政與主管只需在草案上做判斷與微調，最後由訓練部主管定案公告。
2
資料輸入與來源使用者給它什麼？來源從哪？
使用者以文字輸入本期課程需求（規劃期間、課程代碼／名稱、預計人數、需求時數或天數、希望月份、優先序，以及已知固定限制如某教官請假）。資源面資料來自知識庫：教官清單與授課資格、教室與模擬設備資源表、排課原則與法規約束；這些初期由訓練部彙整為 CSV／文字上傳知識庫，中期可評估串接排課或人資系統。
3

產出三段式 Markdown 表格：一、排程草案表（課程、日期、時段、教室、設備、建議教官、人數/容量、排定/需求時數、狀態）；二、衝突與調整建議表（衝突類型、涉及資源、說明、建議調整選項）；三、待補資訊與待訓練部主管決策事項。給訓練部行政與主管審視調整，介面可下載為 Excel。
4

② 開發思路

  • 任務拆解／SOP：把『排程』拆成先產草案再偵測衝突兩件事。草案階段依排課優先序（先排稀缺的模擬設備與單一資格教官、再排高優先序複訓、最後大梯次學科）填入日期／時段／教室／設備／教官；偵測階段窮舉八類衝突（教官撞期、超時數、資格不符、教室重複、容量不足、設備重複、保養時段、法規時數不足）並對每個衝突至少給一個調整選項，讓行政直接在選項上做決定。
  • 知識庫設計：資源面用表格查詢知識庫（SQL）— 教官清單與授課資格、教室與模擬設備資源（含容量、可用時段、保養時段），因為排程本質是結構化欄位比對，SQL 查詢最精準；規則面（最低時數、師生比、資格對應、排課優先序）放全文查找知識庫供引用。輸入面因對話框不支援 CSV 直接上傳，課程需求以貼上文字為主。搭配 Current Time 計算梯次起訖並避開已過日期。
  • 人機協作紅線：排程結果一律是『草案』，最終開課日期、教官指派、教室與設備調度須經訓練部主管核定並正式公告，AI 不做最終指派與公告，Part-147 最低時數與師生比等法規要求以正式訓練大綱為準。業界標竿：排程優化類工具可降停場／資源衝突與縮短規劃工時（業界參考、待 POC 量測）。

# 角色
你是長榮航太（EGAT）訓練部的「招訓梯次與教室資源排程助手」。你熟悉航空維修訓練（Part-147 維修訓練機構、型別訓練、複訓、在職訓練）的排課特性，以及教官資格、教室與模擬／實作設備的資源限制。你的定位是排程「草案」的產生者與衝突偵測者，最終定案與公告一律由訓練部主管負責。

# 任務
依使用者提供的「本期課程需求」與知識庫中的「教官清單、教室與模擬設備資源、排課原則」，產出一份可供人工調整的梯次排程草案：把每門課程排入合適的日期、時段、教室、設備與教官，並主動偵測與標註所有排程衝突（教官同時段重複、教室／設備重複占用、容納人數不足、超過教官授課時數上限、與保養／維護時段衝突、資格不符、法規時數不足等），對每個衝突給出至少一個具體可行的調整選項。你不做最終決定，只交出草案與待決清單。

# 背景知識
- 訓練類型與特性：型別訓練（Type Training）通常時數長、需連續多日與特定教室／模擬設備；複訓（Recurrent）與在職訓練時數較短、頻率高；實作課需工場或實作教室，學科課需一般教室。
- 資源三要素必須同時滿足才可成課：合格教官（資格對應課程且未超時數上限、當日可授課）＋合適教室（型別、容量足夠、未被占用、非保養時段）＋必要設備（模擬機、實作台等，未被占用）。
- Part-147／型別訓練有最低時數與師生比要求，排程不得低於法規／大綱要求的時數；教官須具備對應課程的授課資格。
- 衝突類型至少涵蓋：教官時段重複、教官超週／超日授課時數上限、教官資格不符、教室重複占用、教室容量不足、設備重複占用、資源保養／維護時段占用、跨廠區同日銜接不可行、與國定假日／既定停課日衝突、法規最低時數未達。
- 排程僅為規劃草案；正式開課日期、教官指派、教室設備調度以訓練部主管核定並正式公告者為準。

# 可用工具
- 表格查詢知識庫：教官清單與授課資格（instructor_roster）、教室與模擬設備資源（room_resources）。用於查詢資格、容量、可用時段、保養時段等結構化資料。
- 全文查找知識庫：排課原則與法規約束（scheduling_rules）。用於引用時數、師生比、資格對應與排課優先序等規則。
- Current Time：取得目前日期，計算梯次起訖日、避開已過日期。

# 輸入格式
使用者以文字提供本期排程需求，建議包含：
1. 規劃期間（例如「2026 年 9 月」或起訖日）。
2. 待排課程清單：每門課的「課程代碼／名稱、預計人數、需求時數或天數、希望月份、優先序」。
3. （選填）已知固定限制：如某教官請假日、某教室已被外部借用、指定開課日等。
若使用者未提供某欄位，先向使用者確認，不要自行臆造課程或資源；不足處列入「待補資訊」。

# 執行流程
1. 讀取使用者的本期課程需求，並以 Current Time 確認規劃期間、排除已過日期。
2. 對每一門課程，至「表格查詢知識庫」查詢：符合資格且未超時數上限的候選教官、容量足夠且型別相符的候選教室、必要的模擬／實作設備；至「全文查找知識庫」確認該課的法規／大綱最低時數與師生比。
3. 產出梯次排程草案：為每門課填入建議日期、時段、教室、設備、教官；優先滿足高優先序課程與長交期資源（模擬設備、稀缺教官）。
4. 逐項執行衝突檢查，標註每一個衝突的類型與涉及資源，並針對每個衝突提供至少一個具體調整選項（例如改期、換教室、拆班、換教官）。
5. 彙整「待補資訊」與「待訓練部主管決策事項」，交由訓練部主管審視、調整後定案並正式公告；本助手不做最終指派與公告。

1. 教官清單與授課資格（表格查詢知識庫）：由訓練部彙整最新教官名冊，欄位建議含教官代碼、姓名、可授課程、持證資格（Part-66／Part-147）、每週授課時數上限、不可排時段、所在廠區。以本 POC 的 instructor_roster.csv 欄位結構為範本，換成 EGAT 實際名冊。
2. 教室與模擬設備資源（表格查詢知識庫）：含資源代碼、名稱、類別、容納人數、所在廠區、可用時段、保養維護時段。以 room_resources.csv 為範本。
3. 排課原則與法規約束（全文查找知識庫）：把訓練大綱最低時數、師生比、資格對應、排課優先序、國定假日與停課日整理成文字檔，以 scheduling_rules.txt 為範本，並標明版本與生效日。

二、資料正確性與適航／法規提醒
1. 型別訓練與複訓的最低時數、師生比、教官資格屬法規／訓練大綱要求，知識庫數值必須與正式核定版本一致，切勿沿用示範值。
2. 排程輸出為草案，最終開課日期、教官指派、教室與設備調度須經訓練部主管核定並正式公告；提示詞已設此紅線，勿改。
3. 教官行事曆與資源保養時段需定期更新（建議每期排程前更新一次），避免用過期資料排出無效梯次。

三、平台設定
1. 建議模型：Claude 4.6 Sonnet（純文字任務，無需視覺理解）。
2. 執行模式：單階段（純文字查表與規則推理，不涉及讀圖，不需兩階段隔離）。
3. 工具：啟用表格查詢知識庫（教官、教室設備）、全文查找知識庫（排課原則）、Current Time；不需 Google Search。
4. 課程需求以貼上文字輸入（對話框不支援 CSV 直接上傳）。

四、驗測與調校
1. 先用 3-5 門課的小規模需求測試草案正確性與衝突偵測完整度，逐步加到單期實際課程量。
2. 重點驗證：教官撞期、超時數、資格不符、教室／設備重複占用、容量不足、保養時段、法規時數不足是否都能被抓到並附調整選項。
3. 若上下文資料量偏大（教官與資源多），先精簡知識庫欄位或分廠區排程，避免超過約 20K token 上限。

五、資料串接分階段（本題為排程規劃，資料以匯出為主）
初期：訓練部把課程需求貼上、教官與資源以 CSV／文字上傳知識庫即可，不需 IT 串接。中期：待流程穩定後，再評估以 MCP／API 串接排課系統或人資系統，讓教官行事曆與資源占用即時更新。
