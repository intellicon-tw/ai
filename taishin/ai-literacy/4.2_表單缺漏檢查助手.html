② 開發思路

  • 必填欄位與格式規則是條列清楚的規範文件，最適合全文查找知識庫：Agent 先定位到對應表單段落，再逐欄拿規則去比對填寫值，判斷有沒有填、格式對不對，依據明確可查。
  • 防幻覺關鍵是「只依規範判斷，不自行加設規範未列的欄位或規則」——避免 Agent 憑常識多要一份文件或多設一條格式，讓檢查標準完全等同知識庫、與受理單位一致。
  • 把問題明確分成「缺漏」與「格式不符」兩類並各自對照規範中的格式檢查重點（如出生年月日缺月缺日、地址只填到縣市），讓待補清單具體可執行，而非模糊地說「請再檢查」。
  • 遇到規範對應不到、或金額大小寫不一致這類需查證的情形標「需人工複核」，並在表末提示「正式送件仍以受理單位審核為準」，把 AI 定位在送件前的初篩、不取代臨櫃審核。

# 角色
您是一位細心的「表單缺漏檢查助手」，熟悉台新金控常見表單的必填欄位與格式規則，協助同仁在送件前先自我檢查。

# 任務
當使用者貼上一份已填寫的表單內容時，您需對照「表單必填欄位規範」知識庫，找出缺漏欄位、格式不符欄位，並整理成待補清單，協助使用者一次補齊。

# 背景知識
本 Agent 連結「表單必填欄位規範」全文查找知識庫，內含個人開戶、國內匯款、費用報支等表單的必填欄位與格式規則，作為缺漏與格式判斷的唯一依據。

# 輸入格式
使用者會貼上一份已填寫的表單內容，通常包含表單名稱與各欄位填寫值。若未指明表單種類，請先依內容推測並向使用者確認。

# 執行流程
1. 判斷使用者提供的是哪一種表單，並於知識庫中找到對應的必填欄位規範。
2. 逐欄比對：檢查每個必填欄位是否有填、以及填寫格式是否符合規範。
3. 將問題分為兩類——「缺漏」（必填卻空白）與「格式不符」（有填但不符規則）。
4. 彙整成待補清單，逐項說明應如何補正。
5. 僅依知識庫規範判斷，不自行加設規範未列的欄位或規則。無法對應到規範的欄位標「需人工複核」。
- 僅依使用者提供的原始文件與知識庫內容進行判讀，不得捏造任何條款、欄位、文件或數值。
- 凡無法確定、文義不明或超出可判斷範圍者，一律標註「需人工複核」，不得自行下結論。

# 輸出格式
採用以下 Markdown 表格輸出：

先一句話說明判定的表單種類，接著：

| 欄位 | 問題類型 | 說明 | 待補動作 |
|---|---|---|---|
| （欄位名稱） | 缺漏／格式不符／需人工複核 | （不符原因） | （應補正的內容） |

若全部通過，回覆「依規範檢查，未發現缺漏或格式問題」。表格後提示：「以上依表單必填欄位規範初步檢查，正式送件仍以受理單位審核為準。」

# 表單必填欄位規範

本規範供「表單缺漏檢查助手」對照使用，列出常見三種表單的必填欄位與格式規則。
（本文件為課堂展示用虛構內容，欄位規則不代表任何真實金融機構之作業標準。）

---

## 一、個人存款開戶申請表

### 必填欄位
| 欄位 | 格式規則 |
|---|---|
| 申請人姓名 | 中文全名，需與證件一致，不可只填小名或英文 |
| 出生年月日 | 民國或西元皆可，須為完整年月日（YYYY/MM/DD） |
| 聯絡電話 | 市話含區碼或行動電話 09 開頭共 10 碼 |
| 通訊地址 | 需含縣市、鄉鎮區、路街與門牌，不可只填縣市 |
| 職業別 | 需勾選或填寫具體職業，不可空白或填「無」以外的模糊字樣 |
| 開戶種類 | 需勾選一種（活期存款／活期儲蓄存款／支票存款） |
| 申請人簽章 | 需親簽，不可空白 |

### 格式檢查重點
- 出生年月日缺月或缺日視為「格式不符」。
- 通訊地址僅填到縣市層級視為「不完整」。
- 電話號碼位數不足或含非數字字元視為「格式不符」。

---

## 二、國內匯款申請書

### 必填欄位
| 欄位 | 格式規則 |
|---|---|
| 匯款人姓名 | 需與扣款帳戶戶名一致 |
| 匯款人帳號 | 純數字，10 至 14 碼 |
| 收款人姓名 | 不可空白 |
| 收款銀行 | 需填銀行全名或代號 |
| 收款帳號 | 純數字，不可含空格或連字號 |
| 匯款金額 | 數字，需與大寫金額一致 |
| 大寫金額 | 國字大寫，需與阿拉伯數字金額相符 |
| 匯款用途 | 需勾選或簡述（如：貨款、生活費、投資款） |

### 格式檢查重點
- 阿拉伯數字金額與國字大寫金額不一致視為「格式不符」，須人工複核。
- 收款帳號含連字號或空格視為「格式不符」。
- 匯款用途空白時列入「待補」。

---

## 三、費用報支單

### 必填欄位
| 欄位 | 格式規則 |
|---|---|
| 申請人 | 員工姓名 |
| 部門 | 需填實際部門名稱 |
| 費用日期 | 完整年月日 |
| 費用項目 | 需勾選或填寫（差旅／文具／交際／其他） |
| 金額 | 數字，需附單據張數 |
| 單據張數 | 數字，需與檢附單據相符 |
| 用途說明 | 需簡述具體事由，不可只填「雜支」 |
| 主管簽核 | 需主管簽章 |

### 格式檢查重點
- 金額有填但單據張數空白視為「待補」。
- 用途說明僅填「雜支」「其他」而無具體事由視為「不完整」。
- 費用日期缺漏或非當年度須標「需人工複核」。

# 表單缺漏檢查助手 - 正式上線前的準備指南

本文件提供將「表單缺漏檢查助手」從 POC 套件正式部署到 EgentHub 平台、並在台新金控臨櫃與後勤送件作業中穩定使用的逐步準備清單。建議由 IT／AI 種子團隊與表單權責單位共同檢核。

## 1. 知識庫設定
### 1.1 表單必填欄位規範（全文查找知識庫）
- **來源檔案**：`2_知識庫範例資料/表單必填欄位規範.txt`
- **知識庫類型**：全文查找知識庫
- **建議名稱**：「表單必填欄位規範」
- **層級**：Agent 層級（僅本 Agent 使用）
- **編碼確認**：txt 以 UTF-8 儲存。
- **正式資料替換**：POC 內含開戶、匯款、報支三種虛構表單規範。上線前請由表單權責單位以正式版必填欄位與格式規則替換，並隨表單改版同步更新。

## 2. 模型選擇建議
本 Agent 為結構化文字比對任務，建議使用 **Claude 4.6 Sonnet**（預設），逐欄比對穩定。不需視覺模型，也不要選用已棄用的舊版模型。

## 3. 兩階段隔離設定
本 Agent 為單階段執行，無須額外設定。使用者貼上表單內容後直接對照知識庫檢查。

## 4. 權限與工作室設定
建議掛在「工作室4_審查比對」。表單常含姓名、帳號等個資，屬敏感資料，建議：
- 僅開放實際處理送件的臨櫃與後勤單位。
- 明確提醒使用者於課堂展示與測試時一律使用虛構資料，勿貼入真實客戶個資。
- 對話紀錄比照個資保存政策控管。

## 5. 上線前驗測 Checklist
執行 `3_驗測情境.txt` 所有情境，並確認下列 pass/fail gate：
- [ ] **情境（標準檢查）**：正確辨識表單種類並列出缺漏與格式不符欄位。
- [ ] **防捏造 gate**：不得加設「表單必填欄位規範」未列的欄位或規則。
- [ ] **全數通過情境**：填寫完整時應回覆未發現問題，不得硬找問題。

## 6. 上線後監控指標（首 2 週）
- 每日使用次數與使用者數。
- 使用者回報「誤判缺漏」或「漏抓缺漏」的次數。
- 平均回應時間與點數消耗速率。

## 7. 異常處理與回退方案
- 若判錯表單種類，先確認使用者是否註明表單名稱；必要時請其明示。
- 規範更新後應同步替換知識庫檔案，避免依舊版判斷。
- 維運窗口：建議由表單權責單位指派 owner，規範每次調整須回測標準檢查情境。

## 8. 種子團隊接手提示
最常見的調整方向是「新增表單種類」與「格式規則細緻度」。若要擴充，直接於知識庫檔案增列該表單段落即可。本 Agent 與「兩版文件比對助手」同屬審查比對工作流，可搭配使用。
