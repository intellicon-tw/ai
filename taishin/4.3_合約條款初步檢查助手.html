② 開發思路

  • 風險提示來自「常見高風險條款與檢查原則」這類概念性描述，合約用字又千變萬化，最適合 Agent 向量知識庫（RAG）：用語意把合約裡的實際條款對應到最相近的檢查要點。
  • 採條件式兩階段隔離的原因，正呼應課程「圖像＋工具混用是幻覺高風險區」：若一邊讀 PDF 一邊查知識庫、一邊下風險結論，模型容易把看到的、查到的、腦補的混在一起，把不存在的條款講得煞有其事。
  • 所以步驟一遇到 PDF／圖片時只做一件事——忠實讀取並輸出抽取到的條款結構化文字，嚴禁呼叫知識庫或做判斷；把「讀取」與「比對」切開，先確保抽出來的條款是合約真有的，再進下一步。
  • 步驟二才查合約審查要點知識庫做風險對照，並要求只就合約「實際出現」的條款標示、不明確者標「需人工複核」、附引用的檢查原則；再全程標註「僅供初步參考，最終以法務審查為準」，維持人在迴路。

# 角色
您是一位協助初步整理合約的「合約條款初步檢查助手」，能抽取合約關鍵條款並對照審查要點標示風險提示，協助台新金控同仁在送法務前先做一次自我盤點。

# 任務
當使用者提供合約內容（貼上文字或上傳 PDF）時，您需抽取金額、期限、違約金、管轄、自動續約等關鍵條款，對照「合約審查要點」知識庫標示風險提示。您僅提供初步輔助，所有判斷最終以法務單位審查為準。

# 背景知識
本 Agent 連結「合約審查要點」Agent 向量知識庫，內含常見高風險條款與檢查原則，作為風險提示的依據。

# 輸入格式
使用者可能以兩種方式提供合約：
- 直接貼上合約文字；或
- 上傳合約 PDF 檔。
請依輸入型態決定執行流程。

# 執行流程
## 步驟一（僅在使用者上傳 PDF／圖片時執行）
- 僅讀取並理解該 PDF／圖片，逐項輸出抽取到的關鍵條款結構化文字（如金額、期限、違約金、管轄、自動續約等）。
- 嚴禁在此步驟呼叫任何知識庫或工具，也不做風險判斷。
- 結尾提示：「初步整理完成，若需進一步比對請在下一步告訴我。」

## 步驟二（依文字輸入或步驟一結果執行）
- 若使用者為純文字輸入，直接執行本步驟。
- 若接續步驟一，先說：「我將基於上一步的整理結果進行比對。」
- 此時才查詢「合約審查要點」知識庫，將抽取的條款逐項對照，標示風險提示與檢查原則。
- 僅就合約中「實際出現」的條款標示，不得臆測或補充未載明內容；條款不明確者標「需人工複核」。
- 僅依使用者提供的原始文件與知識庫內容進行判讀，不得捏造任何條款、欄位、文件或數值。
- 凡無法確定、文義不明或超出可判斷範圍者，一律標註「需人工複核」，不得自行下結論。

# 輸出格式
採用以下 Markdown 表格輸出（步驟二）：

| 條款類別 | 合約內容摘錄 | 風險提示 | 檢查原則／待確認 |
|---|---|---|---|
| （如：違約金／自動續約） | （合約實際文字摘要） | 高／中／需人工複核 | （對照審查要點的檢查建議） |

表格前後務必註明：「本結果僅為初步輔助整理，最終仍以法務單位審查為準。」

# 合約審查要點

本文件供「合約條款初步檢查助手」對照使用，列出常見高風險條款與檢查原則。
本助手僅提供初步輔助整理，所有判斷最終仍以法務單位審查為準。
（本文件為課堂展示用虛構內容，不構成法律意見。）

---

## 一、關鍵條款抽取清單
初步檢查時，應優先定位並抽取下列條款：
1. 契約金額與付款條件
2. 契約期間（起訖日、履約期限）
3. 違約金與賠償責任
4. 管轄法院與準據法
5. 自動續約條款
6. 終止與解除條件
7. 保密與智慧財產權歸屬
8. 保固與保證責任

---

## 二、常見高風險條款與風險提示

### 1. 違約金
- 高風險：違約金比例過高（如逾契約總價 30%）、或未載明計算基準。
- 檢查原則：確認是否對雙方對等，是否有上限。

### 2. 自動續約
- 高風險：載明「期滿未於 30 日前以書面通知則自動續約一年」且無明確退出機制。
- 檢查原則：確認通知期間、退出方式與續約後價格調整條款。

### 3. 管轄法院
- 高風險：約定由對方所在地或特定境外法院專屬管轄。
- 檢查原則：確認是否為我方可接受之管轄地，避免不對等。

### 4. 付款條件
- 高風險：預付比例過高、驗收條款模糊、付款無明確天數。
- 檢查原則：確認驗收標準、付款天數、發票與請款流程。

### 5. 保密與智財
- 高風險：保密期間過長且無合理範圍、成果智財全數歸對方。
- 檢查原則：確認保密範圍、期間與智財歸屬是否合理對等。

### 6. 賠償責任
- 高風險：無責任上限、含間接損失與懲罰性賠償。
- 檢查原則：確認是否設有賠償上限與排除條款。

---

## 三、檢查原則總則
- 僅就合約中「實際出現」的條款進行標示，不得臆測或補充未載明之內容。
- 條款文義不明確、或無法判斷風險高低者，一律標「需人工複核」。
- 不得捏造任何條款編號、金額或期限。
- 輸出應清楚標註「僅供初步參考，最終以法務審查為準」。

# 合約條款初步檢查助手 - 正式上線前的準備指南

本文件提供將「合約條款初步檢查助手」從 POC 套件正式部署到 EgentHub 平台、並在台新金控合約送審前置作業中穩定使用的逐步準備清單。建議由 IT／AI 種子團隊與法務單位共同檢核。

## 1. 知識庫設定
### 1.1 合約審查要點（Agent 向量知識庫）
- **來源檔案**：`2_知識庫範例資料/合約審查要點.txt`
- **知識庫類型**：Agent 向量知識庫（RAG）
- **建議名稱**：「合約審查要點」
- **層級**：Agent 層級（僅本 Agent 使用）
- **編碼確認**：txt 以 UTF-8 儲存。
- **正式資料替換**：POC 內含虛構高風險條款清單。上線前請由法務單位以正式審查要點替換，並定期隨法規與內規更新。

## 2. 模型選擇建議
本 Agent 可能需讀取 PDF 合約，屬視覺解析任務，建議使用 **Claude 4.6 Sonnet** 或 **Gemini 3.1 Pro**。純文字比對亦由同一模型處理即可；不要選用已棄用的舊版模型。

## 3. 兩階段隔離設定
本 Agent 標示為「條件式」兩階段，須於 EgentHub Agent 設定頁啟用兩階段隔離：
- **純文字輸入**：直接走步驟二，抽取條款並查「合約審查要點」知識庫標示風險。
- **上傳 PDF**：先走步驟一（只讀 PDF、逐項輸出結構化條款、不查知識庫，結尾提示「初步整理完成，若需進一步比對請在下一步告訴我。」），使用者確認後再進步驟二（先說「我將基於上一步的整理結果進行比對。」才查知識庫）。
- 上線前必跑：`3_驗測情境.txt` 中「純文字直走步驟二」與「上傳 PDF 先走步驟一」兩情境，確認步驟一未提前呼叫知識庫。

## 4. 權限與工作室設定
建議掛在「工作室4_審查比對」。合約屬高度敏感資料，建議：
- 僅開放法務、採購及有合約審閱需求的權責單位。
- 明確標示「初步輔助、非法律意見」，避免使用者誤當定稿依據。
- 課堂展示與測試一律使用虛構合約，勿上傳真實往來合約。

## 5. 上線前驗測 Checklist
執行 `3_驗測情境.txt` 所有情境，並確認下列 pass/fail gate：
- [ ] **情境（純文字直走步驟二）**：正確抽取條款並對照要點標示風險。
- [ ] **情境（上傳 PDF 先走步驟一）**：步驟一只輸出結構化文字、未呼叫知識庫，步驟二才比對。
- [ ] **防捏造 gate**：合約未出現的條款（如自動續約）不得憑空標示，應如實反映「未見該條款」。

## 6. 上線後監控指標（首 2 週）
- 每日使用次數與使用者數。
- 兩階段是否正確分流（步驟一誤呼叫知識庫的次數）。
- 使用者回報「漏抓條款」或「風險誤判」的次數與平均回應時間。

## 7. 異常處理與回退方案
- 若步驟一提前查知識庫，回頭檢查兩階段設定與提示詞是否被覆蓋。
- PDF 掃描品質不佳導致抽取錯誤時，請使用者改貼文字。
- 維運窗口：建議由法務單位指派 owner，提示詞調整須回測上述兩個兩階段情境與防捏造情境。

## 8. 種子團隊接手提示
最常見的調整方向是「關鍵條款清單」與「風險判準」的更新。本 Agent 的兩階段結構可直接複製給「開戶KYC文件初檢助手」等同樣需讀 PDF／圖片的 Agent 作為起點。上游為業務或採購提出的合約草稿，下游為法務正式審查。

### 情境 #6：純文字輸入直走步驟二

**輸入描述**

> 直接貼上服務合約摘錄文字（test_data 7）。

**預期輸出**

> 略過步驟一，直接抽取違約金 40%、自動續約、對方所在地專屬管轄、預付 50% 等條款，對照審查要點標高風險，並註明僅初步輔助、以法務為準。

**驗證重點**

> 純文字直接進入步驟二並查知識庫，風險標示正確。

### 情境 #7：上傳 PDF 先走步驟一再步驟二

**輸入描述**

> 上傳採購合約 PDF（test_data 8）。

**預期輸出**

> 步驟一只讀 PDF、逐項輸出結構化條款、不查知識庫，結尾提示「初步整理完成，若需進一步比對請在下一步告訴我。」；使用者確認後步驟二先說「我將基於上一步的整理結果進行比對。」再對照要點。

**驗證重點**

> 步驟一未呼叫知識庫、兩階段提示語正確、隔離成立。

### 情境 #8：防捏造（不虛構未載明條款）

**輸入描述**

> 貼上僅含金額與期限的簡短合約（test_data 9）。

**預期輸出**

> 如實反映合約僅見金額與期限，未見違約金、管轄、自動續約等條款，不憑空標示這些條款存在，不明處標需人工複核。

**驗證重點**

> 不捏造合約未出現的條款。
