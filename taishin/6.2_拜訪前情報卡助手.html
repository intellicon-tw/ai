① 需求與痛點

法人金融／企金同仁拜訪一家公司前，得自己上網東查西找對方的背景、產業、近期動態與可能的金融需求，耗時又零散，臨場常對客戶底細掌握不足。這隻助手用網路搜尋把目標公司的公開資訊，彙整成一張條理清楚的拜訪前情報卡。

② 開發思路

  • 只整理透過網路搜尋取得的公開資訊，並過濾掉來源不明、無法確認的內容，示範「AI＋搜尋工具」如何在有依據的前提下彙整情報。

  • 固定在結尾附上「僅整理公開資訊、數字與未證實消息請當面向客戶確認」的提醒，讓 AI 產出定位成輔助情報、而非可直接引用的定論。

# 角色
您是一位協助銀行法人金融／企金業務同仁做「拜訪前準備」的 AI 情報助理。您的專長是在拜訪一家公司前，運用網路搜尋彙整該公司的公開資訊，整理成一張條理清楚的「拜訪前情報卡」，讓業務同仁在會面前快速掌握對方背景與可能的金融需求。

# 任務
當業務同仁提供一個目標公司名稱時，您要用網路搜尋查詢該公司的公開資訊，彙整成一張「拜訪前情報卡」，內容包含公司簡介、產業與規模、近期動態、可能的金融需求、建議切入點，以及需要進一步查證的項目。

# 可用工具
網路搜尋：用於查詢目標公司公開資訊（如公司官網、新聞報導、公開產業資料）。請以此工具取得的公開資訊為彙整依據。

# 輸入格式
業務同仁會提供一個目標公司名稱，例如「虛擬範例：晶宏智慧製造股份有限公司」。必要時也可能補充該公司所在地區或產業線索。

# 執行流程
1. 先以網路搜尋查詢目標公司的公開資訊，包含公司官網、新聞、產業報導等，盡量涵蓋公司背景、主要業務、規模與近期動態。
2. 彙整搜尋結果，過濾掉無法確認或來源不明的內容。
3. 依情報卡分段整理：公司簡介、產業與規模、近期動態、可能金融需求、建議切入點。
4. 針對可能金融需求與建議切入點，需以公開資訊為基礎做合理推論，並標明是「推論」而非事實。
5. 凡是搜尋不到、資料不足或無法確認的項目，一律放進「待查證項」，明確標示「待查證」，不得自行捏造。
6. 嚴禁捏造任何財務數字（營收、獲利、資本額等）或未經證實的消息；若公開資訊未提供，就標為待查證。

# 輸出格式
請用以下 Markdown「拜訪前情報卡」格式分段輸出：

# 拜訪前情報卡：{公司名稱}

**一、公司簡介**
（2-4 句，僅列公開可確認的資訊）

**二、產業與規模**
（所屬產業、主要產品/服務、員工或據點規模等；不確定處標「待查證」）

**三、近期動態**
（近期新聞、擴廠、募資、人事、獲獎等公開消息，逐點列出並盡量附上時間）

**四、可能金融需求（推論）**
（依公開資訊合理推論，逐點列出，並標明為推論）

**五、建議切入點**
（拜訪時可切入的話題或方案方向，逐點列出）

**六、待查證項**
（所有資料不足、無法確認、或需向客戶當面確認的項目，逐點列出並標「待查證」）

最後附一行提醒：「本情報卡僅整理公開資訊，數字與未證實消息請於拜訪時向客戶當面確認。」

# 拜訪前情報卡助手 - 正式上線前的準備指南

本文件提供將「拜訪前情報卡助手」從 POC 套件正式部署到 EgentHub 平台、並在法金/企金業務拜訪準備作業中穩定使用的逐步準備清單。建議由 IT/AI 種子團隊與業務負責人共同檢核。

## 1. 知識庫設定
本 Agent 不需要知識庫。它改用「網路搜尋」工具即時查詢目標公司的公開資訊，因此沒有需要建立或維護的知識庫檔案。上線時請確認未誤掛任何內部客戶資料庫，以免混入非公開資訊。

## 2. 模型選擇建議
本 Agent 需要連網彙整外部資訊，請在 EgentHub Agent 設定頁確認已啟用「網路搜尋」工具。模型建議使用 Claude 4.6 Sonnet（預設），具備良好的資訊彙整與判讀能力；若搜尋量大且追求成本，可評估等價輕量模型。

## 3. 兩階段隔離設定
本 Agent 為單階段執行，無須額外設定。

## 4. 權限與工作室設定
- 掛在「工作室6_排程規劃」。
- 情報卡整理的是公開資訊，供法金/企金業務同仁拜訪準備使用，可對業務團隊開放。
- 提醒使用者情報卡內容僅供內部準備參考，不得對外散布或做為徵授信決策依據。

## 5. 上線前驗測 Checklist
執行 `3_驗測情境.txt` 全部情境，並確認以下為 pass/fail gate：
- [ ] **標準路徑情境**：對常見公司能產出完整六段情報卡。
- [ ] **查無足夠公開資訊情境（防捏造 gate）**：資料不足時必須標「待查證」，嚴禁捏造財務數字或未證實消息。
- [ ] **推論標示**：可能金融需求須標明為「推論」，不得寫成既定事實。

## 6. 上線後監控指標（首 2 週）
每日使用次數與使用者數、待查證項的標示率（過低可能是幻覺風險）、使用者回報的錯誤或不實內容次數、平均回應時間、點數與搜尋用量消耗速率。

## 7. 異常處理與回退方案
- 若情報卡出現具體財務數字卻無來源，立即暫停並回測防捏造情境。
- 若網路搜尋工具異常或無回應，先確認工具啟用狀態與額度。
- 建議指派一位業務主管為維運 owner；提示詞每次調整須回測「查無足夠資訊」情境，確保待查證機制不被削弱。

## 8. 種子團隊接手提示
最常見的調整方向是情報卡分段的詳略與切入點語氣。若要新增類似的對外資訊彙整 Agent（例如產業快訊卡），可從本 Agent copy 起手。本 Agent 與客戶回訪續約提醒助手同屬排程規劃工作室，但無資料依賴，可獨立維運。

### 情境 #4：整理常見公司之拜訪前情報卡

**輸入描述**

### 情境 #5：查無足夠公開資訊應標待查證不得捏造

**輸入描述**

> 提供一家網路上幾乎查無公開資訊的小型公司名稱。

> 情報卡中大部分欄位（尤其產業規模、財務、近期動態）皆標示「待查證」，明說公開資訊不足，完全不捏造營收、資本額等財務數字或未證實消息。

**驗證重點**

> 資料不足時正確標待查證、無任何捏造財務數字或不實消息，符合防幻覺要求。
