本頁的提示詞與知識庫多為示範用。要讓 Agent 真正貼合 業務與客戶服務 的實際作業，最關鍵的一步是你提供真實資料，建議補上：客服案件紀錄匯出樣本、技術 FAQ／常見問答、模組產品規格表、Email 回覆範本、銷售報表匯出樣張（皆請去識別化）。資料越完整，Agent 開發得越準、越快。

這是 業務與客戶服務 的專屬資料夾，請把補充資料放這裡，方便我們對應每一題。

業務與客戶服務部門這次填的四題整體品質不錯：泰英中翻譯、技術客服、案件摘要三題的場景、輸入輸出都講得具體，可以直接進 POC。第四題「行銷文宣＋銷售資料分析」方向清楚，但只提到「database 資料龐大、撈取整理花時間」，沒有說是哪套系統、常撈哪些欄位、報表長什麼樣，這題需要先把銷售資料定期匯出成表格（或未來經 MCP 介接）才能落地，建議承辦同仁補一份常用報表範例與欄位清單。另外提醒：翻譯與客服兩題若能提供真實往來信件與 FAQ（去識別化後），Agent 的準確度會明顯提升。以下每一頁對應一個需求，點進去可看到：需求與痛點 → 開發思路 → 完整提示詞 → 知識庫設計 → 建置流程 → 驗測情境。

#001A · 適合

泰英中商務翻譯與書信助手

文件摘要與翻譯型

泰國 Navanakorn 廠與台灣總部日常往來的泰英中商務書信與技術文件，翻譯與回覆速度慢，外語文案的專業度與在地化流暢度不足，溝通摩擦成本高。

 #002A · 適合

太陽能技術客服知識助手

知識庫問答型

模組與系統工程的技術客服問題仰賴資深同仁經驗，第一線人員回答太陽能專業知識的精準度與一致性不足，客戶技術問題的平均回應時間偏長。

 #003A · 適合

客服案件摘要與回覆助手

資料彙整分析型

客服日常需處理大量客戶問題確認、案件紀錄整理、跨部門溝通與回覆內容撰寫，流程高度重複，需要快速且準確地整理資訊與回應需求。

 #004B · 部分適合

行銷文宣與銷售資料分析助手

資料彙整分析型

展會、節慶、產品更新等 email blast 文宣製作花時間；內部銷售資料分析因 database 資料龐大，撈取與整理均花費較多時間，管理資料分析效率待提升。
