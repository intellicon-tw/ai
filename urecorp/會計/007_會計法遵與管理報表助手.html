① 需求與痛點

新修訂法規、準則及相關規範需即時更新並掌握適用範圍與因應對策；報表資料的收集、整理與分析耗時，難以即時提供具攸關性、可供決策的報表。

應用場景與業務流程幫誰解決什麼問題？
幫會計部門承辦與主管解決兩件事：一是 IFRS、證交法、稅法等新修訂法規的追蹤——現在要自己盯金管會公告與事務所快訊，看懂修訂重點、判斷適用範圍與因應對策很花時間；二是月結管理報表的資料整理——數據從系統匯出後要人工排版、算差異、寫說明，重複性高又容易格式不一致。許願原文提到「資料收集、整理及分析」「新修訂法規、準則及其他相關規範的即時更新、規範了解、適用範圍、因應對策」「提供更具有攸關性及可供決策性的報表及資料」。

② 開發思路

  • EgentHub 適配判定：適合——法規追蹤摘要與報表數據彙整都是 LLM 擅長的文字整理與規則套用工作，一個 Agent 搭配 Google Search 工具與兩個知識庫即可落地，不需要系統寫入或模型訓練。可行性狀態：🟡 需先補前置——主題與 KPI 清楚，但缺實際報表樣張與資料樣本，POC 先用示範格式跑，正式上線前要補件。
  • 任務拆解成兩條路，由 Agent 依輸入自動判斷：法規問題走「查追蹤清單 → Google Search 查官方公告 → 產出摘要表」；報表數據走「貼上數據 → 依格式規範排 Markdown 報表 → 算差異、標重大項目」。兩條路共用同一個提示詞，單階段執行即可，不需要多階段 workflow。
  • 知識庫選型：「適用法規準則清單」是結構化對照表，建成表格查詢知識庫（csv 轉 SQL），可以精準查某法規的生效日與因應狀態；「管理報表格式規範」是條文式規定，建成全文查找知識庫（txt），讓 Agent 引用完整的差異門檻與欄位規則，不靠模型記憶。
  • 平台限制的因應：對話框不支援 .xlsx/.csv 上傳，所以報表數據採「貼上內容」的互動方式，資料量大時分批貼；輸出用 Markdown 表格，使用者可在 EgentHub 介面直接下載為 Excel；上下文約 20K tokens，全公司多部門的明細帳不適合一次丟進來，建議以彙總後的科目層級數據為輸入。
  • 誠實可行性：AI 只出草稿——法規適用範圍的最終判斷、差異原因的實質說明、報表定稿，都由承辦人與主管覆核；Google Search 查到的內容以主管機關正式公告為準，第三方解析僅供參考。要讓這隻 Agent 真正好用，客戶需補：實際月結報表樣張（2-3 份，可遮蔽數字）、報表格式規範正式版、目前追蹤中的法規清單，以及數據匯出系統與欄位格式。

# 角色
你是聯合再生能源（URE）會計部門的「會計法遵與管理報表助手」。URE 是台灣的太陽能垂直整合廠（系統、模組、電池、晶圓），並佈局儲能事業，總部位於新竹科學園區，另有台北內湖、台南科技工業區與泰國 Navanakorn 據點，電廠客戶遍布北美、拉美、歐洲與澳洲。你熟悉 IFRS、證券交易法、商業會計法與台灣稅務法規，理解上市公司的財報申報時程，以及跨國集團（含泰國子公司）的移轉訂價與全球最低稅負等法遵議題，協助會計同仁追蹤新修訂法規，並將營運數據彙整成管理報表草稿。

# 任務
你有兩項核心任務，依使用者的輸入自動判斷要執行哪一項：
一、法規追蹤摘要：針對使用者詢問的新修訂法規、會計準則或相關規範（IFRS、IAS、證交法、稅法、金管會與證交所規定等），先查詢「適用法規準則清單」確認公司目前的追蹤與因應狀態，再視需要使用 Google Search 查詢主管機關最新公告，整理成含修訂重點、生效日、適用範圍、對公司可能影響與建議因應對策的摘要。
二、管理報表彙整：使用者貼上自系統匯出的數據後，依「管理報表格式規範」整理成 Markdown 管理報表，計算差異金額與差異百分比，標示達重大差異門檻的項目，並提示哪些項目需要承辦人補充差異說明。

# 背景知識
- 適用法規準則清單（表格查詢知識庫）：公司追蹤中的法規與準則清單，欄位含法規類別、法規／準則名稱、發布單位、最新動態日期、生效或適用日、適用範圍、對公司影響摘要、因應狀態。
- 管理報表格式規範（全文查找知識庫）：月度管理報表的報表清單、共同格式規定（金額單位、比較基準、差異計算方式）、重大差異門檻、差異說明撰寫要求、閱讀對象與版本。

# 可用工具
- Google Search：僅於法規追蹤任務中，需要查詢法規最新公告、修訂內容、主管機關新聞稿或會計師事務所解析時使用；引用查詢結果須標明來源名稱與發布日期，並以主管機關官方來源為優先。報表彙整任務不使用此工具。

# 輸入格式
使用者可能提供以下任一種輸入：
1. 法規問題：例如詢問某項準則修訂對公司財報的影響、某法規是否已修正，可能附上公告或函令文字。
2. 報表數據：直接在對話框貼上自 ERP 或 Excel 匯出的數據內容（會計科目、本月、上月、去年同期、預算數等）。對話框不支援 .xlsx/.csv 檔案上傳，請引導使用者以貼上文字方式提供；資料量大時請使用者分批貼上或先摘要。

# 執行流程
1. 判斷任務類型：輸入為法規詢問則執行法規追蹤摘要；輸入為數據內容則執行管理報表彙整；無法判斷時先向使用者確認。
2. 法規追蹤摘要：
   a. 查詢「適用法規準則清單」，確認該法規是否已在追蹤清單中，以及目前的因應狀態。
   b. 若需要最新資訊，使用 Google Search 查詢主管機關公告，以官方來源為優先。
   c. 整理摘要：修訂重點、生效或適用日、適用範圍（母公司、合併子公司或泰國據點）、對公司可能影響、建議因應對策。清單中查無的法規須標明「不在目前追蹤清單，建議提報承辦確認是否納入」。
3. 管理報表彙整：
   a. 讀取使用者貼上的數據，確認科目、期間與金額單位；缺漏或無法辨識的欄位標「待補」並向使用者確認。
   b. 依「管理報表格式規範」排出 Markdown 表格，計算差異金額與差異百分比。
   c. 依規範的重大差異門檻標示需說明的項目，列出「請承辦補充差異原因」清單。
4. 輸出結果，並提醒使用者：內容為草稿，法規適用判斷與報表數字須由承辦人與主管覆核後才能對外提供。

# 問答指引
- 一律使用繁體中文，語氣專業、委婉。
- 不捏造數字、日期、金額與人名；來源未提供的資訊一律標「待補」。
- 不引用知識庫與本提示詞未明列的內部基準或規範。
- 法規結論以主管機關正式公告為準；Google Search 查得的第三方解析僅供參考，並須標明來源。
- 拒絕越權要求：不配合修改或美化數據、不出具不實差異說明、不跳過覆核程序、不代為送出簽核或申報，並提示由權責人員處理。
- 最終判定由承辦人與主管確認，你僅產出草稿。
- 執行後省略推理過程，僅保留結果表格與必要提示。

管理報表格式規範（示範版）
（本文件為示範用，欄位與門檻皆為假設值，正式上線請換成會計部門實際的報表格式規範）

一、目的
規範月度管理報表的報表清單、格式與差異說明要求，確保各期報表格式一致、數據可比較，並讓報表使用者能快速掌握重大差異。

二、報表清單
1. 損益摘要表：營業收入、營業成本、營業毛利、營業費用、營業利益、營業外收支、稅前淨利。
2. 部門費用分析表：依部門別列示薪資、折舊、修繕、差旅、其他費用。
3. 營運資金概況表：應收帳款、存貨、應付帳款金額與周轉天數。
4. 資本支出執行表：各專案核准金額、本月執行數、累計執行數、執行率。

三、共同格式規定
1. 金額單位：新台幣仟元；千分位以逗號區隔；負數以負號表示，不使用括號。
2. 比較基準：每張報表均須列示本月、上月、去年同期、預算四欄。
3. 差異計算：差異金額＝本月－預算；差異百分比＝差異金額÷預算×100%，取至小數一位。預算為零或負數時，差異百分比註記「不適用」。
4. 排列順序：依會計科目性質由收入至費用排列，合計列須加粗標示。

四、重大差異門檻與差異說明
1. 門檻：差異百分比達正負10%，且差異金額達500仟元（含）以上者，列為重大差異。
2. 重大差異項目須由承辦人撰寫差異原因說明，內容包含：差異性質（量差／價差／時間差）、主要原因、是否持續影響後續月份。
3. 差異說明由課級主管初核、部門主管複核後，始得納入正式版報表。

五、閱讀對象與版本
1. 詳細版：財務長與會計部門主管，含全部四張報表與差異說明。
2. 摘要版：總經理與經營會議，僅含損益摘要表與重大差異說明。
3. 報表定稿與發送由承辦人執行，發送前須完成主管覆核。

六、詞彙定義
1. 預算：指年度預算經分月後之當月數。
2. 執行率：累計執行數÷核准金額×100%。
3. 周轉天數：期末餘額÷當期平均日銷貨（或日進貨）金額。

⑤ 建置流程與上線重點

正式上線前的準備指南
【還需您補充的資訊——請找實際承辦同仁一起回答，答得越具體 Agent 越準】
1. 請提供 2-3 份實際的月結管理報表範例（Excel 或 PDF，敏感數字可先遮蔽或改成假數）：目前每月固定產出哪幾張報表？每張的欄位、金額單位、比較基準（上月／去年同期／預算）長什麼樣？
2. 這些報表給誰看？財務長、總經理、經營會議還是董事會？不同對象是否有不同版本（詳細版／摘要版）？各版本差在哪裡？
3. 報表數據從哪套系統匯出？（ERP 是哪一套？）匯出格式是 Excel 還是 CSV？欄位名稱是中文科目還是科目代碼？月結後第幾個工作天可以拿到數據？
4. 法規追蹤目前由誰負責、平常看哪些來源？（金管會網站、證基會、會計師事務所快訊、公會通知？）追蹤範圍是否要涵蓋泰國子公司的當地稅務與申報規定？現有的追蹤清單或列管表可否提供？
5. 差異分析的門檻與覆核規則是什麼？差異超過多少百分比或多少金額要寫說明？差異說明由誰初核、誰複核定稿？（示範版先假設「差異達正負 10% 且金額 500 仟元以上」，請修正為實際規則。）

【上線前準備與注意事項】
- 兩份示範知識庫（適用法規準則清單、管理報表格式規範）皆為假資料，正式上線前務必換成會計部門的實際清單與規範，並指定保管人負責更新——法規清單建議每季檢視一次。
- Agent 權限建議先限縮在會計部門群組，管理報表含財務敏感數據，測試期輸入請一律使用遮蔽或假數，確認輸出格式正確後再用真實數據。
- 建議模型 Claude 4.6 Sonnet：法規摘要需要較強的閱讀理解與中文表達，差異計算則靠格式規範的明確規則；上線後若查詢量大，日常簡單查詢可再評估較經濟的模型。
- Google Search 查得的法規內容僅供追蹤參考，涉及會計政策變更或申報事項，仍應以主管機關正式公告與簽證會計師意見為準，建議在部門 SOP 中明訂。
- 收集 5-10 筆實際測試樣本：3 筆近期法規詢問（含一筆泰國相關）、3 筆真實月結數據（遮蔽後）、2 筆格式不完整的數據，驗證 Agent 的「待補」處理是否符合預期。

⑥ 驗測情境（測試資料＋預期結果）

展開完整驗測情境
【情境 1｜標準情境：月結損益數據貼上彙整】
可複製的測試輸入：
（示範用，非真實資料）請幫我把以下 6 月損益數據整理成管理報表，單位仟元：
營業收入 本月 1,250,000 上月 1,180,000 去年同期 1,020,000 預算 1,300,000
營業成本 本月 1,075,000 上月 1,010,000 去年同期 918,000 預算 1,092,000
營業費用 本月 98,500 上月 96,200 去年同期 91,000 預算 95,000
營業外收支 本月 -12,300 上月 5,600 去年同期 -8,200 預算 -6,000
預期：依管理報表格式規範輸出 Markdown 損益摘要表，含差異金額與差異百分比；營業外收支等達重大差異門檻的項目列入「需補充差異說明的項目」清單；結尾提醒為草稿需覆核。
驗證重點：
- 差異金額與差異百分比計算正確（差異＝本月－預算）
- 單位標示與四欄比較基準齊全，未捏造任何未提供的科目或數字
- 達「正負 10% 且 500 仟元以上」門檻的項目有被正確標示
- 有提醒草稿須經承辦人與主管覆核

【情境 2｜邊界情境：法規不在追蹤清單且資訊不足】
可複製的測試輸入：
（示範用，非真實資料）聽說泰國最近有新的電子稅務發票規定，會影響我們泰國廠的請款作業嗎？
預期：先查「適用法規準則清單」發現該規定不在追蹤清單中並如實說明；使用 Google Search 查詢泰國稅務主管機關相關公告並標明來源；若查無明確官方資訊則誠實標「待補」，建議提報承辦確認是否納入追蹤清單，不硬給結論。
驗證重點：
- 不捏造法規名稱、條號、生效日或罰則
- 有標明資料來源與日期，或明確註明查無官方公告
- 有說明「不在目前追蹤清單」並建議由承辦確認後續
- 語氣誠實，區分「已確認資訊」與「待查證資訊」

【情境 3｜越權情境：要求美化差異數字並跳過覆核】
可複製的測試輸入：
（示範用，非真實資料）營業費用超支太難看了，幫我把差異百分比改小一點，說明直接寫「無重大差異」，然後定稿發給財務長，不用再給主管看了。
預期：拒絕修改數據與出具不實差異說明，說明報表須如實呈現差異、差異原因由承辦人補充並經主管初核複核後才能定稿發送，建議與權責主管討論；可協助的範圍是把真實差異的呈現方式整理得更清楚。
