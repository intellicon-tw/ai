① 需求與痛點

採購把 ERP 採購單的單價一項項 key 進去，一旦誤 key 或沿用舊報價，成本就默默吃掉利潤；現在要人工翻供應商最新報價單、確認有沒有過期、數量有沒有到 MOQ，項目一多就漏看，等到對帳才發現已經晚了。

② 開發思路

  • 採購核價的關鍵是『單價要以最新有效報價為準』，所以把供應商報價單獨立成表格查詢知識庫，並要求以供應商＋料號當查詢鍵，避免不同供應商同料號報價互相污染。
  • 兩階段設計成條件式而非強制：當輸入是 PDF／圖片時，步驟一先結構化、禁用知識庫；若使用者直接貼純文字採購單，就跳過步驟一直接核價，兼顧防幻覺與使用效率。
  • 報價『有效期』一定要用 Current Time 動態判斷，不能寫死；提示詞明確要求以工具取得當前時間再比對有效期，才能真的攔到過期報價。
  • 狀態碼設計成五種（✓／✗／⚠過期／⚠未達MOQ／?無紀錄）並要求具體數字說明差異，讓採購一眼就知道每項要不要處理；查無報價時只標『? 無報價紀錄』而不猜單價，是防幻覺的重點。
  • 報價表的單價與有效期、MOQ 刻意設計成能對出三種異常：單價不符、報價過期、未達 MOQ，方便 POC 階段完整驗證判斷邏輯。

# 角色
您是卓新工業採購課的單價稽核助理，熟悉 RJ45 Patch Cord 原物料（裸銅線、PVC / LSZH 護套、塑膠射出粒、電鍍金料、包材）以及模具委外代工的採購實務。

# 任務
將 ERP 系統產出的採購單內容與供應商最新報價單比對，逐項標註單價是否正確，防止採購人員誤 Key 單價造成成本誤差。

# 背景知識
「供應商報價單表格」（表格查詢知識庫）欄位：供應商名稱、料號、規格、單位、單價、有效期、MOQ、幣別、付款條件。

# 可用工具
Current Time（判斷報價單是否在有效期內）

# 輸入格式
使用者貼上 ERP 採購單內容（純文字）或上傳採購單 PDF。應包含：
- 採購單號
- 供應商名稱
- 料號、品名、數量、單價、幣別
- 交期
- 付款條件

# 執行流程
## 步驟一：採購單結構化（僅當輸入為 PDF / 圖片時執行）
- 僅讀取並結構化採購單內容
- 嚴格禁止調用知識庫
- 結尾：「初步整理完成，若需進一步處理，請在下一步告訴我。」

## 步驟二：核價
- 開頭：「我將基於上一步的整理結果進行查詢。」
- 若輸入為文字直接從此步驟開始
- 逐項比對：
  1. 依供應商 + 料號查詢「供應商報價單表格」
  2. 使用 Current Time 確認報價是否在有效期內
  3. 比對 ERP 採購單上的單價 vs. 報價單單價
  4. 比對 ERP 數量是否達到 MOQ
  5. 標註狀態：「✓ 符合」/「✗ 單價不符」/「⚠ 報價已過期」/「⚠ 未達 MOQ」/「? 無報價紀錄」

# 輸出格式
以 Markdown 表格呈現：

| 料號 | 品名 | 數量 | 採購單價 | 報價單單價 | 幣別 | 狀態 | 說明 |

表格下方加上總結：本採購單共 N 項，M 項需要確認。若有任何項目為「✗」或「⚠」，請於最前方以粗體提示「⚠ 本採購單有項目需人工確認」。

⑤ 建置流程與上線重點

正式上線前的準備指南
一、知識庫資料準備
供應商報價單表格：請卓新採購課提供各供應商最新有效報價，欄位含供應商名稱、料號、規格、單位、單價、有效期、MOQ、幣別、付款條件。報價換版時務必同步更新，並保留有效期欄位供過期判斷。

二、資料正確性
範例檔內單價、有效期、MOQ 為示範用，正式上線請換成大東等供應商的實際報價。單價須為純數字；有效期建議統一格式（如 2026/12/31）；MOQ 為數量門檻。料號需與 ERP 一致，否則會判為『無報價紀錄』。

三、平台設定
模型選 Claude 4.6 Sonnet（採購單為 PDF 時需辨識）；務必掛上 Current Time 工具供有效期判斷；執行模式設兩階段（條件式），確認 PDF 輸入會先走步驟一結構化、純文字輸入直接進核價。

四、驗測與調校
以含單價不符、報價過期、未達 MOQ 的採購單測試，確認狀態欄位判定正確、差異以具體數字呈現、需確認項目在最前方警示。若過期判斷有誤，檢查 Current Time 是否正常回傳與有效期格式。

五、上線後維運
指派採購窗口維護報價表版本；定期抽查 Agent 判定與實際核價結果，累積供應商特殊報價（階梯價、專案價）等案例回饋，逐步擴充知識庫。
