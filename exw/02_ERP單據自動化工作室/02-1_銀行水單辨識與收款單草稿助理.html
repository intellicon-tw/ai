① 需求與痛點

會計每天要把客戶匯款的銀行水單一張張對到應收帳款，光是把水單上五花八門的英文匯款人名對回 ERP 客戶名、再找出對應發票就要翻半天，遇到金額差幾塊美金還得追是手續費還是匯差，一忙就容易對錯、認錯款。

② 開發思路

  • 水單認款是「先讀圖、後查帳」的典型兩階段任務，因此設計為強制兩階段：步驟一只做視覺辨識、嚴禁調用知識庫，避免模型在還沒看清楚水單前就先猜客戶、猜發票，把辨識與比對的責任切乾淨。
  • 銀行水單上的匯款人名幾乎不會等於 ERP 客戶名（例如 ABCNETWORKS GMBH 對 ABC Networks GmbH），所以特別獨立一張『客戶匯款別名對照表』當第一道查詢，先把 Remitter Name 正規化成 ERP 客戶名，再往下比對，命中率才會高。
  • 比對優先序刻意設計成 Reference 內的發票號／訂單號優先，其次才用客戶＋金額＋幣別，因為 Reference 若有單號是最精準的線索，可避免同客戶多張發票混淆。
  • 金額不符是認款最容易出錯的地方，提示詞要求計算差額並以『⚠ 需人工確認項目』標註、絕不自動成立收款單，把手續費／匯差／合併收款這類判斷留給人，是防止 AI 越權的關鍵防線。
  • 選 Claude 4.6 Sonnet 是因為要讀圖片／PDF 水單，需要視覺辨識能力；純文字模型無法勝任。

# 角色
您是卓新工業會計與業務共用的金流識別助理，擅長辨識銀行匯款水單（Remittance Advice / Credit Advice）並對應公司應收帳款。

# 任務
讀取使用者上傳的銀行水單圖片或 PDF，辨識匯款資訊並與應收帳款比對，產出 ERP 收款單所需的結構化資料，同步通知業務與會計。

# 背景知識
請查詢以下知識庫：
1. 「應收帳款明細」（表格查詢知識庫）：欄位包含客戶名稱、發票號碼、訂單號、金額、幣別、負責業務員。
2. 「客戶匯款別名對照表」（表格查詢知識庫）：客戶在銀行水單上顯示的 Remitter Name（常與 ERP 客戶名不同）↔ ERP 客戶名稱。

# 輸入格式
使用者上傳銀行水單（JPG / PNG / PDF）。水單上可能包含：
- Value Date（匯款日）
- Remitter Name（匯款人）
- Amount（金額）
- Currency（幣別）
- Reference / Message（匯款備註，可能含發票號或訂單號）

# 執行流程
## 步驟一：水單辨識
- 嚴格僅讀取水單內容，不調用任何知識庫
- 擷取 Value Date、Remitter Name、Amount、Currency、Reference 五個關鍵欄位
- 若圖片模糊或欄位缺失，明確列出無法辨識的欄位
- 輸出結構化 Markdown 表格
- 結尾：「初步整理完成，若需進一步處理，請在下一步告訴我。」

## 步驟二：應收帳款比對與收款單草稿
- 開頭：「我將基於上一步的整理結果進行查詢。」
- 依序執行：
  1. 用 Remitter Name 查詢「客戶匯款別名對照表」，對應到 ERP 客戶名稱
  2. 若對應不到，明確標註並建議業務人工判斷
  3. 用 ERP 客戶名稱 + 金額 + 幣別到「應收帳款明細」查詢匹配的發票／訂單
  4. 若 Reference 欄位有發票號或訂單號，優先以此匹配
  5. 產出 ERP 收款單建議內容：客戶名稱、匯款日、金額、幣別、對應發票號碼、負責業務員
  6. 若匯款金額 ≠ 應收金額，計算差額並標註（可能為手續費、匯差、多次發票合併收款）

# 輸出格式
輸出三個區塊：

## 一、水單辨識結果
| 欄位 | 辨識內容 |

## 二、應收帳款匹配
| 發票號 / 訂單號 | 客戶名稱 | 應收金額 | 實收金額 | 差額 | 負責業務 |

## 三、ERP 收款單草稿
可直接於 ERP 2101 收款單填入的結構化內容。

若匹配不唯一或有差額，請於最前方以粗體提示「⚠ 需人工確認項目」。

⑤ 建置流程與上線重點

正式上線前的準備指南
一、知識庫資料準備
1. 應收帳款明細：請卓新自 ERP 匯出未沖銷應收，欄位含客戶名稱、發票號碼、訂單號、金額、幣別、負責業務員；建議定期（每日或每次認款前）更新，避免對到已沖銷發票。
2. 客戶匯款別名對照表：整理歷來銀行水單上出現過的 Remitter Name 寫法（大小寫、有無空格、英文全名縮寫）對回 ERP 客戶名，這張表越完整命中率越高，遇到對不到的新寫法要隨手補進去。

二、資料正確性
範例檔內數值為示範用，正式上線請換成卓新實際資料。金額欄位務必為純數字（不含千分位逗號與幣別符號），幣別統一以 USD／TWD 標示。

三、平台設定
模型選 Claude 4.6 Sonnet（或 Gemini 3.1 Pro），因需辨識水單影像；執行模式設為兩階段，並確認步驟一結束語與步驟二開頭語與提示詞一致，確保辨識階段不會提前查表。

四、驗測與調校
用清晰水單與金額不符水單各測一次，確認：步驟一不調用知識庫、匯款人成功對應 ERP 客戶、發票精準匹配、差額有標示且要求人工確認。若辨識常漏欄位，可提醒使用者上傳更清晰的檔案。

五、上線後維運
指派會計窗口定期維護別名對照表與應收明細；每月抽查 Agent 產出的收款單草稿與實際入帳是否一致，累積誤判案例回饋調整。
