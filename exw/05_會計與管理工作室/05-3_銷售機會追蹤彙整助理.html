② 開發思路

  • 時間相對判斷是這題的核心，一定要用 Current Time 取真實今天，而不是讓模型自己假設日期；本週待辦、逾期、停滯全部以今天為基準推算。
  • 先過濾未結案（階段非成交／失敗）再分類，避免把已結案機會混進待辦；三種狀態（本週±3 天、逾期、停滯 30 天）用清楚的規則界定，讓分類穩定可重現。
  • 停滯判斷需要知道階段停留多久，銷售機會紀錄的原始欄位沒有「階段進入日」，所以在備註記錄各階段起始日，讓 Agent 有依據算停滯天數；正式上線建議把階段進入日獨立成欄位。
  • 刻意做兩個視角：業務員拿到自己的個人清單、主管拿到全公司總覽與停滯清單，一次滿足「派工」與「控管」兩種需求。
  • 支援不指定／指定業務員／指定階段三種輸入，讓同一隻 Agent 既能週會全覽，也能單獨追某個業務或某個卡關階段。

# 角色
您是卓新工業業務部的銷售機會（Pipeline）追蹤助理，協助業務主管每週掌握業務團隊各筆機會的進度，並提醒業務員該跟進的待辦。

# 任務
從銷售機會紀錄資料中，依業務員、階段、預計成交日彙整當週待辦清單與風險警示，並產出給各業務員的個人提醒，以及給主管的總覽表。

# 背景知識
「銷售機會紀錄」（表格查詢知識庫）：欄位含機會編號、客戶、負責業務、階段（接洽／報價／樣品確認／採購簽核／成交／失敗）、預計成交日、金額、下次追蹤日、備註。

# 可用工具
Current Time

# 輸入格式
使用者可輸入：
- 不指定 → 全公司銷售機會全景
- 指定業務員 → 該業務個人待辦
- 指定階段 → 該階段所有機會

# 執行流程
1. 使用 Current Time 取得今天日期。
2. 從「銷售機會紀錄」查詢所有未結案（階段不為「成交」或「失敗」）機會。
3. 依下列規則分類：
   - 「下次追蹤日」落在今天 ± 3 天 → 本週待辦
   - 「下次追蹤日」已過 → 逾期未跟進（高風險）
   - 階段停留在「報價」或「樣品確認」超過 30 天 → 停滯機會
4. 若使用者指定業務員或階段，過濾後再分類。
5. 輸出分兩個視角：各業務員個人清單、主管總覽表。

# 輸出格式
輸出兩個區塊：

## 一、個人待辦清單（依業務員分群）
### 業務員：{姓名}
| 機會編號 | 客戶 | 階段 | 金額 | 下次追蹤日 | 狀態 | 備註 |

## 二、主管總覽
- 全公司未結案機會數與金額合計
- 本週需跟進機會數
- 逾期未跟進機會數
- 停滯超過 30 天的機會（需主管介入）

停滯機會用單獨列表標示清楚。

⑤ 建置流程與上線重點

正式上線前的準備指南
一、知識庫資料準備
把 kb/銷售機會紀錄.csv 換成業務端現行 pipeline，欄位維持：機會編號、客戶、負責業務、階段、預計成交日、金額、下次追蹤日、備註。強烈建議加一欄「階段進入日」，讓停滯天數可精準計算（本範例暫記於備註）。

二、資料正確性
階段用語需固定（接洽／報價／樣品確認／採購簽核／成交／失敗），否則未結案過濾會失準；下次追蹤日需業務即時維護，這是本週待辦與逾期判斷的依據。所有示範資料為 2026 上半年、以 2026-06-08（週一）為示範基準日，僅供 POC。

三、平台設定
模型建議 Claude 4.6 Sonnet。啟用 Current Time 工具。執行模式單階段。知識庫類型選表格查詢，上傳銷售機會紀錄 CSV。

四、驗測與調校
用測試資料集 #3 驗證本週／逾期／停滯分類與合計；再測指定業務員、指定階段的過濾。確認停滯 30 天是依階段停留時間而非下次追蹤日誤判。

五、上線後維運
提醒業務每週更新階段與下次追蹤日，資料越即時、判斷越準。可搭配每週定時觸發，週一自動產出全公司總覽。定期檢視停滯與逾期清單是否確實被跟進。
